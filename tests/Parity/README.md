# Original PHPStan assertion parity

`fixtures/` contains all 31 original type fixtures from `tests/reference`, preserving their namespaces and actual expressions. Only the 638 `assertType` and 5 `assertSuperType` calls are adapted. `manifest.json` records each original file, line, expected type, profile, and syntax normalization.

Run `MAGO_BINARY=/path/to/mago php tests/run-parity.php`. The default binary is `vendor/bin/mago`. Select one configuration using `--profile web`, `console`, `custom`, `params`, `awkward`, `definition`, or the focused `header` subset. `--json` returns every mismatch and native error for inspection. A profile fails if a comparison is missing, an expectation differs, or the worker fails. Native diagnostics remain visible but only fail a profile with `--strict-native`: the original PHPStan type inference tests deliberately include invalid writes and assert inferred types independently of diagnostics. The package's separate production corpus keeps strict native validation.

Run `php tests/run-parity.php --self-test` to verify that three valid comparisons pass and two deliberately invalid comparisons fail. A literal `1` must fail an exact `int` expectation and pass a supertype `int` expectation, proving that exact assertions check both containment directions. The self-test succeeds only when it observes exactly those five outcomes.

`php tests/run-parity.php --project-patches` selects `config/web-project-patches.toml` for the Web profile and leaves other profiles unchanged. The separate `project-patches/Measurement.php` declaration resolves two generic property assertions, yielding 636/643 overall. It still fails on the remaining seven assertions. Original fixtures, expectations and the default configuration are preserved. See [the experiment report](../../docs/project-stubs.md) for limitations and rejected alternatives.

The test-only node hook compares native semantic types. Exact assertions require containment in both directions; supertype assertions require the actual type to be contained by the expected type. No comparison uses printed type strings, and no expected type is changed to match the analyzer's current output.

Expected PHPDoc types live in global companion functions and are wrapped in `Parity\ExpectedType<T>` so a `never` expectation cannot terminate the analyzed call. PHPStan's `*NEVER*` spelling becomes `never`. PHPStan's unsupported `static(Class)` syntax becomes a `Parity\StaticType<Class>` marker; the hook reconstructs native late-static metadata before comparing. These transformations preserve the expected type's meaning.

The installed Yii version determines whether logger payloads also contain `yii\log\PsrMessage`. A test-only `Parity\LogPayload` marker preserves this conditional expectation on both supported Yii branches without changing the reference snapshot.

Each profile uses its original configuration, Composer plus a narrow autoloader for the original support classes, and an analysis-only Yii declaration generated by the package's `StubGenerator`. The original test bootstrap is never loaded. Generated stubs are never required by the PHP worker.

To rebuild artifacts after changing the reference snapshot or generator, `php tests/run-parity.php --generate-patch` emits an `apply_patch` patch. The generator is read-only and does not modify fixtures itself. Apply the emitted patch with the editor's native patch tool. Existing comparison failures remain visible; `current-results.json` is a fixed report snapshot, not a Mago inference baseline or suppression list.

CI saves the full default run with `composer test:parity -- --json > "$RUNNER_TEMP/yii2-parity.json"` (still exits 1 on known mismatches), then requires `php tests/check-parity-regressions.php "$RUNNER_TEMP/yii2-parity.json"`. The guard checks all six profiles and compares multisets of code, message, primary relative filename and line for mismatches and native errors. Only removal of saved issues is accepted; new/changed/duplicated diagnostics or incomplete/invalid reports fail. Host paths and issue order do not matter. It prints real passed/expected counts and remaining failures, so green means no regression, not full parity. It neither rechecks semantic types nor changes actual/expected types, and never automatically refreshes the snapshot.
